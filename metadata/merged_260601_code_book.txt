WHAT THIS FILE IS
-----------------
A plain-text description of every column in merged_260601.csv, written so a
colleague who has never seen the raw data can understand and analyse it.

The CSV is produced by process_csv_v3.py, which reads the per-participant
PsychoPy export files in csvs/dat_260601/, keeps a subset of columns, renames
them to friendly names, derives a few new columns, and stacks all participants
into one table.


THE EXPERIMENT IN ONE PARAGRAPH
-------------------------------
Listeners hear a short /di/ syllable whose fundamental frequency (F0, "pitch")
has been digitally manipulated, and on every trial they (a) judge the pitch
DIRECTION (does it go high / mid / low) and (b) reproduce the perceived pitch by
moving a slider that maps to a frequency in Hz. The base sound is
07_di_150hz_75db_250ff.wav: a /di/ syllable at 150 Hz, 75 dB. Stimuli differ in
how much the F0 is shifted (delta_f, in Hz), in which direction (rising "p" /
falling "n" / flat), and in WHERE in the syllable the shift happens (delta_t, in
ms). Each listener completes the same stimulus set twice, once named as TONE
block and once named as CV block.


DATASET SHAPE
-------------
- Rows: 5040   (one row = one trial)
- Columns: 61
- Participants: 40  (each did exactly 126 trials = 63 TONE + 63 CV)
- Recruitment groups (labID): 32 online (Prolific) + 8 in-lab

GRAIN / "LONG" FORMAT
- Each row is a single trial.
- PER-TRIAL columns change from row to row (the stimulus, the response, RT...).
- PARTICIPANT-LEVEL columns are summaries that repeat identically across all
  126 rows of that participant (e.g. demographics, met_score, every catch_*
  column, catch_n_found, goodbye.stopped). Collapse to one row per participant
  before treating these as per-person values, or you will count them 126x.


KEY DERIVED RELATIONSHIPS (worth knowing before you analyse)
------------------------------------------------------------
1. Stimulus filename encodes the condition:
       main_files/trial_di/07_di_150hz_75db_250ff-<delta_f><dir>-<delta_t>.wav
   e.g.  ...-40p-100.wav  ->  delta_f=40 Hz, dir=p (rising), delta_t=100 ms
         ...-000-120.wav  ->  flat baseline (delta_f=0, dir=0, delta_t coded 0)

2. Correct direction is fixed by the stimulus direction:
       dir = p (rising)  -> corr_dir_di = h (high)
       dir = n (falling) -> corr_dir_di = l (low)
       dir = 0 (flat)    -> corr_dir_di = m (mid)

3. Accuracy of the direction judgement:
       is_correct = TRUE  iff  response_dir == corr_dir_di

4. Pitch-match slider -> frequency in Hz:
       response_f = 100 + (final_rating - 1) * 5
   So slider 1 -> 100 Hz, slider 11 -> 150 Hz (= base), slider 21 -> 200 Hz,
   in 5-Hz steps.

5. final_rating is the unified slider value: it equals tone_slider.response on
   TONE-block rows and cv_slider.response on CV-block rows (verified identical).

DATA-CLEANING CHECKLIST (please read before analysis)
================================================================================
- One row = one trial. De-duplicate to participantID before using any
  participant-level column (Group B, all catch_* columns, catch_n_found,
  met_score, goodbye.stopped); otherwise each value is counted 126 times.
- Identify the block with tone_trials.thisN (TONE) vs cv_trials.thisN (CV).
- final_rating == 11 can be an imputed default for a missing response. One tone
  trial has no slider response at all. Decide how to handle before averaging.
- residence_country and country_of_origin are free text and need normalising.
- language is JSON - parse it; don't treat it as a plain string.
- birthyear has at least one implausible value (1925) - validate.
- response_time and goodbye.stopped are both in SECONDS.
- trial_tone_list and trial_i_list are entirely empty in this file.
